القرار وسببه
نختار Next.js لهذا الدليل، لثلاثة أسباب تخص مشروعنا تحديدا:
موقعنا يحتاج صفحات وبحثا ونموذجا يكتب بيانات. Next.js يعطي التوجيه والواجهة الخلفية في مشروع واحد، فلا نربط مشروعين ونحن في البداية.
التوجيه المبني على الملفات يجعل بنية المشروع مقروءة، وهذا يفيدك أنت ويفيد الأداة الوكيلة التي تقرأ مشروعك.
حجم المجتمع يعني أن أي رسالة خطأ ستجد لها إجابة، وهذا يهم المبتدئ أكثر من أي ميزة تقنية.
ومتى لا يكون الاختيار الصحيح؟ إذا كان موقعك محتوى ثابتا بلا تفاعل فـ Astro أخف وأنسب. وإذا كنت تبني لوحة تفاعلية بلا صفحات عامة فـ React مع Vite أبسط.

# دليل الخدمات

## أوامر
تشغيل: npm run dev
بناء: npm run build
اختبارات: npm test
فحص: npm run lint

## قرارات
الموقع عربي واتجاهه من اليمين إلى اليسار على مستوى المستند.
استخدم الخصائص المنطقية في CSS لا left و right.
الصفحات لا تقرأ مصدر البيانات مباشرة، بل تستدعي lib/data فقط.
كل تحقق من المدخلات يتكرر على الخادم مهما كان تحقق المتصفح.
لا any في الأنواع.

## أعراف
أسماء المكونات بصيغة PascalCase، وأسماء الملفات المساعدة بصيغة kebab-case.
كل نص ظاهر للمستخدم بالعربية.
الخلاصة والخطوة التالية
بنيت موقعا حقيقيا: بمتطلبات مكتوبة، وبنية مقررة، وطبقة بيانات نظيفة، ونموذج آمن، وتصميم يعمل على الهاتف، ونشر بخطة تراجع. الأهم أنك تعرف لماذا كل قرار اتخذ.
ماذا تبني بعده
أضف لوحة إدارة بسيطة لإضافة المزودين بدل تعديل ملف البيانات يدويا.
انقل البيانات إلى قاعدة بيانات حقيقية — طبقة lib/data تجعل ذلك تغييرا في ملف واحد.
أضف مصادقة إن احتاج مشروعك حسابات، وابدأ بحل جاهز موثوق لا بحل من عندك.
أعد بناء المشروع نفسه بإطار آخر لتفهم ما الذي كان من الإطار وما كان منك.
بقية السلسلة
Claude Code من الصفر إلى الاحتراف — لإتقان الأداة نفسها.
تعلم البرمجة مع Claude Code — إن شعرت أن الأساسيات ناقصة.
ابن تطبيقك الأول مع Claude Code — الانتقال من الويب إلى الهاتف.
