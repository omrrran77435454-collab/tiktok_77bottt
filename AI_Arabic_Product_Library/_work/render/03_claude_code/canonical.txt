الواجهات المتاحة
التوثيق يذكر أن Claude Code يعمل على عدة واجهات، وكلها تتصل بالمحرك نفسه، فملفات CLAUDE.md والإعدادات وخوادم MCP تعمل عبرها جميعا:
الطرفية Terminal: الواجهة الكاملة، وهي التي يركز عليها هذا الدليل.
VS Code: إضافة تعرض الفروق داخل المحرر ومراجعة الخطة وسجل المحادثات.
JetBrains: إضافة لـ IntelliJ و PyCharm و WebStorm وغيرها، وتتطلب تثبيت الـ CLI منفصلا.
تطبيق الحاسوب: تطبيق مستقل لمراجعة الفروق بصريا وتشغيل عدة جلسات جنبا إلى جنب.
المتصفح: تشغيل المهام الطويلة بلا إعداد محلي على claude.ai/code.
ما الذي يتطلب اشتراكا
التوثيق يذكر أن معظم الواجهات تتطلب اشتراك Claude أو حساب Anthropic Console، وأن تطبيق الحاسوب يتطلب اشتراكا مدفوعا. كما تدعم واجهات الطرفية و VS Code و JetBrains مزودين خارجيين.
ما الذي يجيده فعلا
أتمتة العمل المؤجل: كتابة اختبارات لكود بلا اختبارات، وإصلاح أخطاء الفحص، وحل تعارضات الدمج، وتحديث الاعتماديات.
بناء ميزات وإصلاح أخطاء: يخطط، ثم يكتب عبر عدة ملفات، ثم يتحقق.
العمل مع Git مباشرة: تجهيز التغييرات وكتابة رسائل الـ commit وإنشاء الفروع وفتح طلبات الدمج.
الربط بأدواتك عبر MCP، والتخصيص بالمهارات والخطافات.
متى لا تستخدمه
لا تستخدمه على كود لا تفهمه ولا تنوي مراجعته. الأداة تنفذ، والمسؤولية عن مراجعة ما نفذ تبقى عليك. وهذه ليست نصيحة عامة: التوثيق نفسه يضع بندا اسمه مسؤولية المستخدم، ويقول إن Claude Code لا يملك إلا الصلاحيات التي تمنحها، وأنك مسؤول عن مراجعة الكود والأوامر المقترحة قبل الموافقة.
التثبيت والتحقق والتحديث
التوثيق يوصي بالمثبت الأصلي Native Install. المسارات التالية منقولة من صفحة التوثيق الرسمية وقت مراجعة هذا الدليل.
macOS و Linux و WSL
المثبت الأصلي — الطريقة الموصى بها
curl -fsSL https://claude.ai/install.sh | bash
Windows
PowerShell
irm https://claude.ai/install.ps1 | iex
موجه الأوامر CMD
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
أي صدفة أنت فيها
التوثيق يعطي علامة مميزة: إذا ظهرت رسالة أن && ليست فاصل جمل صحيحا فأنت في PowerShell لا في CMD. وإذا ظهر أن irm أمر غير معروف فأنت في CMD لا في PowerShell. موجه PowerShell يبدأ بـ PS C:\ بينما موجه CMD يبدأ بـ C:\ بلا PS.
Git for Windows على ويندوز الأصلي
التوثيق ينصح بتثبيت Git for Windows على ويندوز الأصلي حتى يستطيع Claude Code استخدام أداة Bash. وبدونه يستخدم PowerShell كأداة الصدفة. أما إعدادات WSL فلا تحتاج Git for Windows.

لماذا اسمان لوضع واحد
الوضع الذي يراجع كل إجراء اسمه Manual في الـ CLI وفي claude --help وفي إضافتي VS Code و JetBrains وفي تطبيق الحاسوب، لكن قيمته في الإعدادات هي default، وهي القيمة التي تستخدمها الخطافات وتكاملات الـ SDK. ويقبل الـ CLI الاسم manual كمرادف، مثل claude --permission-mode manual.
كيف تبدل الوضع
داخل الـ CLI: مفتاحا Shift+Tab.
في VS Code: مؤشر الوضع. وفي تطبيق الحاسوب: محدد الوضع.
عند التشغيل: claude --permission-mode plan مثلا.
من ملف إعدادات: المفتاح permissions.defaultMode.
في أي وضع تبدأ جلستك
التوثيق يوضح أن Claude Code يأخذ الوضع من أول ما ينطبق: العلم --permission-mode أو --dangerously-skip-permissions، ثم permissions.defaultMode في ملف إعدادات، ثم الافتراضي المدمج. وعلى خطط Pro و Max و Team في الطرفية أو عبر إضافة VS Code، الافتراضي المدمج هو وضع auto. أما مع claude -p أو الـ Agent SDK أو خطة Enterprise أو مفتاح Console فالافتراضي هو default.
قيمتان لا تعملان من ملفات إعدادات المشروع
التوثيق يذكر أن ضبط "auto" داخل .claude/settings.json أو .claude/settings.local.json لا يسري، وأن ضبط "bypassPermissions" في هذين الملفين لا يسري أيضا وتبدأ الجلسة في وضع Manual. بقية القيم تسري من أي ملف إعدادات.
ما لا يوافق عليه أي وضع تلقائيا
هذه القائمة من التوثيق مهمة لأنها تعني أن حتى أخطر وضع يبقى فيه سياج. لا يوافق Claude Code تلقائيا في أي وضع، بما في ذلك bypassPermissions، على:
الأدوات التي تطابق قاعدة سؤال صريحة.
الأدوات التي تتطلب تفاعل المستخدم مثل أداة AskUserQuestion.
عمليات rm و rmdir التي تستهدف مسارا حرجا — ولا توافق عليها قاعدة سماح ولا خطاف.
ضمانات المراسلة بين الجلسات.
ويذكر التوثيق أيضا أن قواعد المنع deny تمنع في كل وضع بما فيه bypassPermissions، بينما قواعد السماح allow لا أثر لها داخل bypassPermissions.
الوضع الخطر ومتى يجوز
قبل أن تفكر في تخطي الأذونات
الوضع bypassPermissions، ومعه العلم --dangerously-skip-permissions، ليس إعدادا افتراضيا ولا اختصارا للراحة. التوثيق يشترط لتشغيل مهمة غير مراقبة بهذا الوضع عزلا حقيقيا: حاوية أو جهاز افتراضي أو بيئة تشغيل معزولة، وعلى لينكس و macOS تشغيله بمستخدم غير الجذر.
لا تستخدمه على جهازك الشخصي وعلى مستودع فيه أسرار أو صلاحيات نشر.
بديل عملي أفضل من تخطي الأذونات
إذا كان دافعك كثرة الأسئلة، فالتوثيق يعرض مسارا أنظف: وضع Manual مع صندوق Bash الرملي في وضع السماح التلقائي. تشغله بـ claude --permission-mode default ثم /sandbox وتختار auto-allow. وتبقى قواعد المنع سارية، وتبقى قواعد السؤال التي تسمي أمرا بعينه — مثل Bash(git push *) — تسأل.
أمثلة إطلاق بأوضاع مختلفة
claude --permission-mode default
claude --permission-mode plan
claude -p "run the test suite" --permission-mode dontAsk \
  --allowedTools "Bash(npm test)" "Read"

مراجعة التغييرات والتراجع عن خطأ
هذا الفصل هو شبكة الأمان. أي شخص يستخدم أداة وكيلة سيمر بلحظة يعدل فيها الوكيل شيئا لم يكن يجب أن يعدل. المهم أن تعرف كيف ترجع.
قاعدة المراجعة قبل الاعتماد
راجع الفرق أولا شغل /diff وانظر ما تغير فعلا، لا ما قيل لك إنه تغير.
شغل الاختبارات قبل أي commit، لا بعده.
اقرأ ما لا تفهمه إذا وجدت تغييرا لا تفهم سببه، اسأل عنه قبل الاعتماد.
اعتمد على دفعات صغيرة تغيير صغير مراجع أفضل من عشرة ملفات تعتمدها دفعة واحدة.
نقاط الاستعادة Checkpointing
التوثيق يفرد صفحة مرجعية لـ Checkpointing، ويصفها بأنها إرجاع الكود والمحادثة إلى نقطة سابقة داخل الجلسة نفسها. وهي مختلفة عن التفريع: التفريع ينسخ المحادثة إلى مسار جديد، بينما الاستعادة ترجع بك إلى الوراء. كما تذكر صفحة الجلسات أن قائمة الاستعادة تحتوي مدخلا للجلسة السابقة يتيح الرجوع إلى ما قبل /clear داخل نفس عملية Claude Code.
شبكة أمان لا تعتمد على الأداة
أفضل حماية ليست ميزة داخل Claude Code بل عادة في Git. اجعل كل جلسة عمل تبدأ من حالة نظيفة معروفة:
قبل أن تبدأ جلسة تعديل
git status
git checkout -b feature/my-task
claude
إذا ساءت الأمور
git diff
git checkout -- src/app.js
git stash
git reset --hard
احذر من هذا الأمر تحديدا
git reset --hard يحذف كل التغييرات غير المعتمدة نهائيا، وما حذفه لا يسترجع من Git. شغل git diff وانظر ماذا ستخسر قبل تنفيذه، أو استخدم git stash الذي يحفظ التغييرات بدل أن يمحوها.
حدود مجلد العمل
التوثيق يذكر حماية مهمة: في وضع Manual يستطيع Claude Code الكتابة فقط في المجلد الذي بدأ فيه ومجلداته الفرعية، ولا يستطيع تعديل ملفات في مجلدات أعلى دون إذن صريح. كما يسألك في وضع Manual قبل قراءة مسارات خارج هذا الحد بأدوات القراءة والبحث. ولهذا لا تشغل Claude Code من مجلد المنزل.
العمل مع Git والفروع وطلبات الدمج
Claude Code يعمل مع Git مباشرة: يجهز التغييرات، ويكتب رسائل الـ commit، وينشئ الفروع، ويفتح طلبات الدمج. الفائدة الحقيقية تظهر عندما تجعل ذلك جزءا من سير عمل منضبط لا أمرا عابرا.
سير عمل الفرع الواحد
افتح فرعا لكل مهمة لا تعمل على الفرع الرئيسي مباشرة.
اطلب خطة قبل التنفيذ في وضع التخطيط، لتراجع النطاق قبل أن يكتب سطر.
نفذ ثم راجع /diff ثم الاختبارات ثم الاعتماد.
commit صغير ومعنوي رسالة تشرح لماذا لا ماذا.
افتح طلب دمج واترك للمراجع فرصة حقيقية للفهم.

الخطافات تشغل أوامر صدفة قبل أو بعد إجراءات Claude Code، مثل التنسيق التلقائي بعد كل تعديل ملف، أو تشغيل الفحص قبل الـ commit. وهي الآلية الوحيدة التي تنفذ بغض النظر عما يقرره Claude، ولهذا فالتوثيق يوجهك إليها عندما تريد منعا حقيقيا لا مجرد توجيه.
إدارة الخطافات
/hooks
خطاف أول يستحق الإعداد
خطاف PreToolUse يمنع إجراء قبل وقوعه. استخدمه لمنع الكتابة في ملفات حساسة أو تشغيل أوامر محظورة في مشروعك، بدل الاعتماد على تعليمة نصية في CLAUDE.md قد لا يلتزم بها.
ويذكر التوثيق خطافا مفيدا للتشخيص اسمه InstructionsLoaded، يسجل أي ملفات تعليمات حملت ومتى ولماذا، وهو مفيد لتصحيح القواعد المرتبطة بمسارات.
الإضافات Plugins
التوثيق يفرد صفحات لاكتشاف الإضافات الجاهزة عبر الأسواق، وإنشاء الإضافات، وإنشاء سوق إضافات وتوزيعه، وتقييد إصدارات اعتماديات الإضافة. تعامل مع أي إضافة أو مهارة من طرف ثالث كما تتعامل مع أي برنامج تنزله: اعرف مصدرها، واقرأ ما تطلبه، ولا تثبت ما لا تحتاجه.
الوكلاء الفرعيون والعمل المتوازي وأشجار العمل
عندما تكبر المهمة، لا تحل بجلسة واحدة أطول بل بتقسيمها. التوثيق يوفر أكثر من آلية لذلك، ولكل واحدة موضعها.
الوكلاء الفرعيون Subagents
التوثيق يذكر إمكانية تشغيل عدة وكلاء يعملون على أجزاء مختلفة من المهمة في وقت واحد، مع وكيل قائد ينسق العمل ويوزع المهام الفرعية ويدمج النتائج. والصفحات المتعلقة تشمل: تشغيل الوكلاء بالتوازي، وإنشاء وكلاء فرعيين مخصصين، وإدارة عدة وكلاء عبر عرض الوكلاء، وتنسيق فرق من جلسات Claude Code، والمراسلة بين الجلسات، وتنسيق الوكلاء الفرعيين على نطاق واسع عبر سير العمل الديناميكي.
ما لا ترثه الوكلاء الفرعية
التوثيق يوضح أن الذاكرة التلقائية للمحادثة الرئيسية لا تحمل في الوكلاء الفرعيين، والاستثناء هو التفريع الذي يرث المحادثة الأصلية ورسالة النظام. وللوكيل الفرعي ذاكرة تلقائية خاصة به في مجلد منفصل إذا فعلت.
أشجار العمل Worktrees
أشجار عمل Git تتيح تشغيل جلسات متوازية معزولة على فروع منفصلة، وللتوثيق صفحة مخصصة لها. الفائدة العملية: تجرب مقاربتين في وقت واحد دون أن تتداخل تغييرات إحداهما مع الأخرى، ودون تبديل الفروع في مجلد واحد.
شجرة عمل لكل تجربة
git worktree add ../experiment-a -b experiment-a
cd ../experiment-a
claude

MCP: ربط Claude Code بأدواتك
بروتوكول MCP معيار مفتوح لربط أدوات الذكاء الاصطناعي بمصادر بيانات خارجية. به يستطيع Claude Code قراءة مستندات التصميم في Google Drive، وتحديث تذاكر Jira، وسحب بيانات من Slack، أو استخدام أدواتك الخاصة.
من أين تبدأ
إدارة خوادم MCP
/mcp
/mcp reconnect <server>
/mcp disable <server>
التوثيق يفرد صفحة بداية سريعة لربط أول خادم من طرف إلى طرف، وصفحة أوسع لربط Claude Code بالأدوات عبر MCP، وصفحة إدارية للتحكم في وصول خوادم MCP على مستوى المؤسسة.
أمان MCP
ما يقوله التوثيق بوضوح
قائمة خوادم MCP المسموحة تضبط داخل كود مصدر مشروعك كجزء من إعدادات Claude Code التي يودعها المهندسون في نظام التحكم بالإصدارات.
التوثيق يشجع على كتابة خوادمك بنفسك أو استخدام خوادم من مزودين تثق بهم، ويذكر صراحة أن Anthropic تراجع الموصلات مقابل معايير الإدراج قبل إضافتها إلى الدليل، لكنها لا تدقق أمنيا ولا تدير أي خادم MCP.
الخوادم الجديدة تتطلب تحقق ثقة عند أول استخدام. ولاحظ أن التحقق معطل عند التشغيل غير التفاعلي بعلم -p.
قاعدة عملية
لا تضف خادما لا تعرف ماذا يقرأ وماذا يكتب.
أعط كل خادم أقل صلاحية تكفي مهمته.
راجع قائمة الخوادم المفعلة دوريا وأوقف ما لم تعد تستخدمه.
على مستوى الفريق، اجعل قائمة الخوادم مراجعة في طلب دمج مثل أي كود.
الأمان: الأسرار ومراجعة الأوامر والمحتوى غير الموثوق
أداة تشغل أوامر في جهازك تحتاج انضباطا أمنيا. هذا الفصل يجمع ما يقوله التوثيق الرسمي، لا نصائح عامة.
الحمايات المدمجة
نموذج قائم على الأذونات: في وضع Manual يبدأ Claude Code بصلاحيات قراءة فقط، ويسأل قبل تعديل ملف أو تشغيل أمر.
أوامر قراءة فقط: يشغل مجموعة مدمجة مثل ls و cat و git status دون سؤال.
حد مجلد العمل: لا يكتب خارج المجلد الذي بدأ فيه ومجلداته الفرعية دون إذن.
صندوق Bash الرملي: عزل نظام الملفات والشبكة لأوامر Bash، يضبط بـ /sandbox.
تحقق الثقة: أول تشغيل على مستودع وأي خادم MCP جديد يتطلبان تحقق ثقة.
تخزين آمن للاعتمادات: المفاتيح والرموز تخزن في سلسلة مفاتيح macOS عند توفرها، وتحمى بصلاحيات الملفات على Windows و Linux.
حقن التعليمات Prompt Injection
حقن التعليمات أسلوب يحاول به مهاجم تجاوز تعليمات المساعد أو التلاعب بها عبر إدراج نص خبيث. التوثيق يذكر عدة حمايات، من أهمها عمليا:
الأوامر التي تجلب محتوى من الويب مثل curl و wget لا يوافق عليها تلقائيا افتراضيا. في وضع Manual تسأل مثل أي أمر غير قرائي. ولمنعها كليا أضفها إلى permissions.deny.
جلب الويب يستخدم نافذة سياق منفصلة لتجنب حقن تعليمات خبيثة في المحادثة.
في وضع Manual، الأوامر المشبوهة تتطلب موافقة يدوية حتى لو كانت في قائمة السماح سابقا.
أفضل الممارسات مع المحتوى غير الموثوق
راجع الأوامر المقترحة قبل الموافقة.
تجنب تمرير محتوى غير موثوق مباشرة إلى Claude.
تحقق من التغييرات المقترحة على الملفات الحرجة.
استخدم أجهزة افتراضية لتشغيل السكربتات واستدعاء الأدوات، خصوصا عند التعامل مع خدمات ويب خارجية.
بلغ عن السلوك المريب بـ /feedback.
والتوثيق نفسه يذيل ذلك بتحذير مهم: رغم أن هذه الحمايات تقلل المخاطر بدرجة كبيرة، لا يوجد نظام محصن تماما ضد كل الهجمات.
الأسرار: القاعدة التي لا تكسر
لا تكتب مفتاحا ولا كلمة مرور ولا رمزا داخل الكود أبدا.
ضعها في ملف .env واقرأها من متغيرات البيئة.
أضف .env إلى .gitignore قبل أن تنشئه، لا بعده.
أنشئ .env.example فيه أسماء المتغيرات بلا قيم، وأودعه في المستودع.
إذا تسرب مفتاح إلى Git فلا يكفي حذفه في commit جديد: أبطل المفتاح وأنشئ غيره.

إدارة السياق والمشاريع الكبيرة
المشروع الكبير لا يدار بجلسة أطول. يدار بتقليل ما يدخل السياق وبتقسيم العمل.
ماذا يملأ سياقك
شغل /context لترى ما يستهلك السياق حاليا. التوثيق يوضح أن ملفات CLAUDE.md تحمل في بداية كل جلسة وتستهلك رموزا إلى جانب محادثتك، ولهذا يستهدف أقل من 200 سطر لكل ملف. والقواعد المرتبطة بمسارات تحمل فقط عندما يعمل Claude على ملفات مطابقة، وهي الوسيلة الرئيسية لتقليل الضجيج في مستودع كبير.
خمس عادات تقلل استهلاك السياق
جلسة واحدة لهدف واحد. عند تغير الهدف، /clear.
اطلب من Claude قراءة ملفات محددة بدل استكشاف المستودع كله.
استخدم قواعد المسارات بدل ملف CLAUDE.md ضخم.
حول الإجراءات المتكررة إلى مهارات تحمل عند الحاجة فقط.
استخدم /compact مع تعليمات موجهة بدل تركه يلخص كل شيء بالتساوي.
ضغط موجه بدل ضغط عام
/compact keep architecture decisions and edited file names; drop debugging detail
المستودعات الكبيرة
التوثيق يفرد صفحة لإعداد Claude Code في مستودع أحادي monorepo أو قاعدة كود كبيرة، ويذكر إعداد claudeMdExcludes لتخطي ملفات CLAUDE.md الخاصة بفرق أخرى لا تخص عملك. والأنماط تطابق على المسارات المطلقة بصيغة glob، ويمكن ضبطها في أي طبقة إعدادات.
.claude/settings.local.json
{
  "claudeMdExcludes": [
    "**/monorepo/CLAUDE.md",
    "/home/user/monorepo/other-team/.claude/rules/**"
  ]
}
ما لا يمكن استبعاده
التوثيق يذكر أن ملفات CLAUDE.md الخاصة بسياسة مدارة لا يمكن استبعادها، لضمان سريان تعليمات المؤسسة بغض النظر عن الإعدادات الفردية.
تقسيم المهمة الكبيرة
اكتب النطاق أولا ما الداخل وما الخارج، في ملف تعود إليه.
قسم إلى مراحل لكل مرحلة مخرج لا إلى مهام بلا مخرج ملموس.
جلسة لكل مرحلة وسمها باسم المرحلة لتجدها لاحقا.
سجل القرارات في CLAUDE.md حتى لا تنقض في المرحلة التالية.
راجع بعد كل مرحلة قبل أن تفتح المرحلة التي بعدها.
